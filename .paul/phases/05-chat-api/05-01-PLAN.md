<objective>
## Goal
Build the `/api/chat` POST endpoint — the single backend that powers the AI advisor on all surfaces (dashboard widget + Teams bot). Accepts an employee/team context plus a free-text question, injects burnout data from the DB, calls the configured LLM, and returns an advisory response.

## Purpose
All future surfaces (dashboard chat widget in Phase 07, Teams bot in Phase 08) depend on this endpoint existing. Build it first so both surfaces can be wired to the same backend.

<acceptance_criteria>

## AC-1: Chat endpoint returns advisory response
```gherkin
Given an authenticated HR analyst or manager
When they POST to /api/chat with { "employee_id": "<uuid>", "message": "Why is this person at risk?" }
Then the response contains { "reply": "<LLM response>", "context_used": { "score": float, "top_signals": [...] } }
And HTTP status is 200
```

## AC-2: Context injection — burnout data enriches the prompt
```gherkin
Given a valid employee_id
When the chat endpoint processes the request
Then it fetches the latest burnout score + top_features for that employee from the DB
And injects them into the LLM system prompt before calling the model
```

## AC-3: Team-level query (no employee_id)
```gherkin
Given an authenticated manager
When they POST to /api/chat with { "team_id": "<uuid>", "message": "What's the overall team risk?" }
Then the endpoint aggregates scores for that team and responds with team-level advisory
```

## AC-4: LLM provider is configurable
```gherkin
Given LLM_PROVIDER=azure_openai in env
When the endpoint is called
Then it uses Azure OpenAI client with AZURE_OPENAI_ENDPOINT + AZURE_OPENAI_KEY

Given LLM_PROVIDER=ollama in env
When the endpoint is called
Then it uses the Ollama HTTP API at OLLAMA_BASE_URL
```

## AC-5: RBAC — only hr_analyst and manager roles can call /chat
```gherkin
Given a user with role "employee"
When they POST to /api/chat
Then the response is 403 Forbidden
```

<task type="auto">
  <name>Task 2: Implement /api/chat route</name>
  <files>api/routes/chat.py</files>
  <action>
    Create `api/routes/chat.py` with:

    **Request schema:**
    ```python
    class ChatRequest(BaseModel):
        message: str = Field(..., min_length=1, max_length=1000)
        employee_id: str | None = None   # UUID str
        team_id: str | None = None       # UUID str
    ```

    **Response schema:**
    ```python
    class ChatResponse(BaseModel):
        reply: str
        context_used: dict  # {"score": float|None, "top_signals": list, "scope": "employee"|"team"|"general"}
    ```

    **Endpoint `POST /chat`:**
    1. Require role hr_analyst or manager (use `require_role(["hr_analyst", "manager"])` pattern from existing routes)
    2. If `employee_id` given: query latest BurnoutScore for that employee_id from DB; extract `score` and `top_features`
    3. If `team_id` given: query all employees in team, average their scores, collect top signals
    4. Build system prompt:
       ```
       You are CognitiveSync, an AI advisor for enterprise workforce wellbeing.
       You help HR analysts and managers understand burnout risk data and take action.
       Be concise, empathetic, and actionable. Never identify individuals by name.

       [If context available:]
       Current risk context:
       - Burnout score: {score:.0%} ({level})
       - Top contributing signals: {signals}
       ```
    5. Call LLM based on `settings.llm_provider`:
       - `azure_openai`: Use `openai` package with `AzureOpenAI` client
       - `ollama`: POST to `{ollama_base_url}/api/generate` via httpx async
    6. Return `ChatResponse`

    Avoid: storing the conversation history (stateless per request — privacy constraint).
    Avoid: logging the user's message or the LLM response (contains potentially sensitive context).
  </action>
  <verify>
    curl -X POST http://localhost:8000/api/chat \
      -H "Authorization: Bearer $TOKEN" \
      -H "Content-Type: application/json" \
      -d '{"message": "What should I do about high burnout risk?"}' \
    | python -m json.tool
  </verify>
  <done>AC-1, AC-2, AC-3, AC-5 satisfied: endpoint returns reply + context_used, respects RBAC</done>
