<objective>
## Goal
Replace `output/dashboard.html` (demo-only static file) with a production SPA in `output/dashboard/` served by FastAPI, with live data binding to the real API and role-based views for HR analyst and manager roles.

## Purpose
The demo HTML is hardcoded — no real auth, no live data. This plan ships the production UI that makes the platform usable beyond demos: authenticated, role-aware, and data-live.

## Output
- `output/dashboard/` — production frontend directory
- `api/routes/frontend.py` — FastAPI static mount + login redirect
- Live data binding to `/api/v1/scores`, `/api/v1/scores/team-summary`, `/api/v1/cascade-map`
- Role-based rendering: HR analyst sees all employees; manager sees team summary only
</objective>

## AC-1: Dashboard served by FastAPI
```gherkin
Given the FastAPI server is running
When a browser requests GET /dashboard/
Then it returns the production index.html with 200 OK
And static assets (app.js, styles.css) are resolvable
```

## AC-2: Login flow works
```gherkin
Given the dashboard login page is loaded
When the user selects a role and clicks Sign In
Then the app calls GET /api/v1/demo/token?role={role}
And stores the returned JWT in localStorage
And redirects to the main dashboard view
```

## AC-3: HR Analyst / HR Admin sees all employees
```gherkin
Given a user is logged in as hr_analyst or hr_admin
When the dashboard loads
Then it calls GET /api/v1/scores and GET /api/v1/scores/team-summary
And renders an employee risk table with burnout score, risk level, top signals, and cascade risk per employee
And renders team summary cards with avg score and member count
```

## AC-4: Manager sees team-only view
```gherkin
Given a user is logged in as manager
When the dashboard loads
Then it calls GET /api/v1/scores/team-summary (not /scores directly)
And renders team summary cards only (no individual employee rows)
And the employee table section is hidden or absent
```

## AC-5: 401 redirects to login
```gherkin
Given a stored JWT is expired or absent
When the dashboard makes an API call and receives 401
Then the app clears localStorage and redirects to the login screen
```

<task type="auto">
  <name>Task 2: Production dashboard frontend (HTML + JS + CSS)</name>
  <files>output/dashboard/index.html, output/dashboard/app.js, output/dashboard/styles.css</files>
  <action>
    Create `output/dashboard/index.html`:
    - Single HTML file. No framework, no CDN dependencies (fully offline-capable).
    - Two views controlled by CSS display toggle: `#login-view` and `#app-view`
    - Login view: role dropdown (hr_admin, hr_analyst, manager) + "Sign In" button
    - App view: header with role badge + sign-out button, then role-specific content panels:
      - `#employee-panel`: table of employees (shown for hr_admin, hr_analyst only)
      - `#team-panel`: team summary cards (shown for all roles)
      - `#cascade-panel`: cascade risk section (shown for hr_admin, hr_analyst only)
    - Load `styles.css` and `app.js` from relative paths

    Create `output/dashboard/app.js`:
    - On page load: check localStorage for `cs_token` and `cs_role`; if present, skip to loadDashboard()
    - `signIn(role)`: calls `GET /api/v1/demo/token?role={role}`, stores `{token, role}` in localStorage, calls loadDashboard()
    - `loadDashboard()`:
      - Show `#app-view`, hide `#login-view`
      - Set role badge text
      - If role is hr_admin or hr_analyst: fetch scores + team-summary + cascade-map in parallel (Promise.all)
      - If role is manager: fetch team-summary only; hide employee/cascade panels
    - `apiFetch(path)`: wrapper that adds `Authorization: Bearer {token}` header; on 401 calls `signOut()`
    - `renderEmployeeTable(scores)`: builds HTML rows; columns: pseudo_id (truncated 8 chars), risk_level, score (2dp), confidence interval, cascade_risk, top signals
    - `renderTeamCards(teams)`: builds card HTML per team; shows team_id (truncated), avg_score, member_count, risk distribution
    - `renderCascadePanel(cascadeMap)`: shows cascade propagation edges as a simple list
    - `signOut()`: clears localStorage, shows login view, hides app view
    - Use `score_to_risk_level` logic: score >= 0.7 → HIGH (red), 0.4–0.7 → MEDIUM (amber), < 0.4 → LOW (green)

    Create `output/dashboard/styles.css`:
    - Clean, minimal design. Dark header (#1a1a2e), white content area, card grid layout
    - Risk level color coding: .risk-high { color: #e74c3c }, .risk-medium { color: #f39c12 }, .risk-low { color: #27ae60 }
    - Responsive table with sticky header
    - Team cards: CSS grid, 3 columns min 280px
    - No external fonts or icon libraries — system fonts only
  </action>

  </verify>
